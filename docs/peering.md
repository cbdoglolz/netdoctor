# 双节点联动（v0.3.7 测试版）

两个节点均运行 Go 原生服务和独立数据库。管理网页为各自 LAN IPv4 地址的 8088；联动为 LAN HTTPS 8099，仅提供 GET /snapshot。保持现有网关、DNS、代理、IPv6和防火墙配置，不开启自动切换或网络接管。

## 配对与授权

首次启动在 config 中生成 peers.json、peer.crt、peer.key。默认 enabled=false，不开启 8099。每台拥有独立随机 node ID、只读 token 和 ECDSA 证书，文件与 config 权限受限。

由受信任的部署端读取两台自身身份、只读 token 和证书 SHA-256，分别填写对端配置后重启本应用。当前没有网页自助配对接口，不使用 root 密码作为联动令牌，也不将登录会话发送给对端。

配置结构示例（所有值为占位符，不可直接使用）：

```json
{
  "enabled": true,
  "id": "本机32位十六进制身份",
  "name": "节点 A",
  "token": "本机64位随机十六进制令牌",
  "peers": [{
    "id": "对端32位身份",
    "name": "节点 B",
    "url": "https://192.168.50.2:8099",
    "fingerprint": "对端证书DER的64位SHA256十六进制",
    "token": "对端只读令牌"
  }]
}
```

最多 8 个明确私有 LAN IP，禁止 HTTP、公网地址、DNS 名称、URL 用户名密码、路径/查询及重定向。HTTPS 使用固定指纹信任，不依赖浏览器安装自签名证书，并检查有效期与返回节点 ID。证书或令牌更换需重新配置对端；禁用 enabled 后重启关闭监听。

不要提交/分享 peers.json、peer.key、其备份或生产响应。peer.crt 与指纹本身不包含私钥。设备 root 有权读取这些文件；本方案不是防御已被攻破的 root。

## 展示和数据口径

- 节点联动页汇总设备观察，以 IP + MAC 归类，来源分开显示；不是永久身份合并。
- 每台接口与设备累计流量单独展示，不构造两台相加的全网总流量。
- 远端本机快照有新鲜公网请求交付证据、身份匹配时，可向本机列表和拓扑补充“远端证据”路径，不把它改成本机亲自观察。
- 同一个 IP 下 MAC 不同、随机 MAC 或缺少 MAC 时，可能保留多条记录；不能为了减少行数强行合并。
- 远端连接失败不保留为新鲜数据；快照过期或明显时钟偏差显示 stale。节点主机掉电与应用停止不能单靠失败请求区分。

## 共享备注

仅交换手动名称、类型、型号、图标、分组和对应 IP。远端标注经过校验，只在本机没有手动名称时补充显示；本机 config.json 不被远端覆盖，远端补充也不被递归导出。

不共享/执行网关选择、主动监测开关、代理配置、DNS配置、升级命令、账号或管理密码。两端都有手工标注时保留各自结果，在联动页提示名称差异；这不是字段级双向写入同步。

## 故障与恢复

每轮拉取后等待约15秒，请求最长6秒，响应最多8MiB。服务重启保留身份、证书和配对配置；主服务退出会取消拉取并关闭联动监听。端口冲突显示监听错误；证书/身份不匹配拒绝读取。

当前重点验证同 LAN 两台 x86 iStoreOS。跨网段、防火墙转发、多于两台、大量数据、长期压力、证书轮换和大时钟偏差仍需独立验收。默认不开放 WAN 规则；是否从其他网络可达仍由用户已有网络策略决定。
