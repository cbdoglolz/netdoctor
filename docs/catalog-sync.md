# 公共资料自动同步与持久副本 · v0.4.1

## 范围与数据归属

.6 是公共资料的唯一编辑中心，.144 保存独立持久副本。新增节点加入中心的复制目标后自动接收公共资料，不需要节点之间两两同步。当前最多 8 个目标，加入与权限配置仍由部署端完成，没有网页自助注册。

本阶段同步设备备注、类型、型号、分组、预设/上传图标，以及已经保存的上网路径/物理拓扑坐标。监测开关、手动网关关系、路由/DNS/代理、系统凭据、节点流量历史和控制策略不在本次同步范围。公共资料副本不等于可直接接管的完整管理中心备份。

公共记录携带 IP 和可获得的 MAC；MAC 不符时不套用，界面记录警告。没有 MAC 的手动节点按配置地址/节点标识映射。当前不是永久设备身份系统：设备更换 IP 后需管理中心重新确认资料关联。

## 流程

1. 中心从现有设备配置和已保存布局生成公共内容，计算 SHA-256；内容不变不增加版本号。
2. 发生变化时分配递增 revision，将 catalog.json 原子持久保存，并保留最近 8 个旧内容版本文件。
3. 每约 5 秒核对目标节点版本与摘要。仅在内容不同时发送完整公共快照（最大 2 MiB），尚未采用逐字段增量传输。
4. 接收节点验证独立令牌、中心 ID、协议、版本、摘要、大小和字段；拒绝旧版本与同版本不同内容，保留已有副本。
5. 写入临时文件，同步文件内容、原子替换并同步目录后才确认备份（Windows 测试环境不执行目录同步）。相同版本重复送达不重复写盘。
6. 中心核对返回的节点 ID、版本与摘要，界面区分已保存并备份、仅本机保存/待同步、失败及确认过期；恢复连接后自动重试。

备注与布局保存接口会尝试完成复制并返回准确消息。多个目标串行处理，目标不可达时保存等待可能延长；后台失败不将旧确认当作当前备份成功。

## 离线与重启

受管节点显示来自本地 catalog.json 的资料，不依赖实时 peer payload。管理中心停止后继续显示最后保存的备注、图标和布局，显示最后修改、持久保存及联系时间；节点重启后读取同一副本。原始采集仍由节点独立完成。

管理中心不可用时公共资料只读，不自动升主；本机监测开关可单独调整。管理中心恢复后只允许更高版本向前复制，不自动接受较旧中心覆盖已有副本。若中心盘损坏或备份恢复造成版本倒退，接收端报冲突，需管理员核对并恢复正确数据；本阶段没有版本任期、管理权接管或自动灾难恢复。

## 布局与显示

公共布局使用 device:IP 和辅助节点命名空间保存，接收后映射到本机节点 ID。避免 .6 的 doctor 位置误套到 .144 的 doctor。受管页面约每 10 秒重新读取布局，未保存的临时拖动不属于备份。

启用公共目录后，原有只读联动的“本机手工名称优先/远端补充”不再决定公共资料；中心为唯一来源。受管页面的公共字段禁用，提供中心入口；本机监测开关与网络设置保留。设备记录清空/从中心配置移除时保留公共清除记录，防止接收节点旧备注复活。

## 文件与权限

- config/catalog-settings.json：enabled、managerID、managerURL、独立接收 token 和复制目标 peers（含 syncToken）；0600，禁止发布。
- config/catalog.json：本机当前公共资料与版本，0600。
- config/catalog-backup-00.json 至 07.json：最近旧内容版本，管理员可核查恢复，尚无网页恢复入口。
- config/catalog-import-report.json：首次导入报告；原配置和历史库停止采集后备份到 backup-v041。

复用现有 LAN 8099 TLS 监听，新增 POST /catalog；固定证书指纹、私网地址限制、禁重定向。复制令牌独立于快照和控制令牌；快照令牌不能复制资料，接收端不能反向覆盖管理中心。网页 /api/catalog 仅返回状态，不返回令牌或系统配置。

首次迁移以中心现有公共字段优先，其他节点独有的公共记录可导入；冲突原值保留于私密导入报告和原始备份，不自动双向合并。本次实机迁移检查未发现独有待导入记录或冲突。

## 边界

目前只有公共资料自动持久复制。未实现流量历史复制、控制策略备份、完整监测规则同步、网页冲突解决、历史恢复或管理中心接管；同一 ESXi/共享存储同时故障仍需外部备份。中心内并发编辑采用最后保存结果，不提供字段级编辑合并。
