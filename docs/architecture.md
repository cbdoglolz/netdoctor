# 架构与后续接入

本文记录原型阶段的架构目标。v0.2.0 已新增原生 Go 服务、真实只读采集和版本更新接口；当前实现范围与限制以 README 和 CHANGELOG 为准。SQLite、完整流量、物理拓扑及规则诊断仍为后续目标。

## v0.1 已实现

浏览器 → `NetworkService.getSnapshot(mode, scenario, range)` → 演示适配器 → 统一快照 → 六个页面。

快照包含设备、指标、拓扑关系、域名活动、能力清单及告警。观测数据携带来源、观测时间和可用状态；拓扑另有已确认/推测标记。`null` 表示缺失值，不能转换成零。前端不持有路由器凭据。

当前服务是同步固定数据接口，后续接入需升级为异步读取并补充加载、请求失败和取消处理。公共数据含义应保留，页面不能自行编造缺失值。当前模拟范围只切换 24 小时和 7 天；存储设置尚无实际清理行为。

## 真实监测的目标架构（尚未实现）

单台 x86 软路由内：采集适配器 → Go 本机服务 → 规则诊断 → SQLite → 受认证的接口 → 静态前端。

- 用 procd 管理服务，LuCI 提供入口；保留系统现有管理首页。
- 与 ubus/rpcd 会话及最小权限 ACL 集成。服务不提供任意命令执行接口，不对 WAN 默认开放。
- 本机状态读取 ubus、接口统计、系统资源；设备发现结合邻居表、DHCP 租约、受控探测。
- `nlbwmon` 用于本机可见 conntrack 流量统计，不把端口映射当成精确应用识别。
- 支持时读取 `lldpd` 邻居信息与 AP 关联记录；不支持的链路允许用户标注，保留来源和置信程度。
- DNS 来源按实际环境适配，优先读取现有日志/接口；不会为采集默认替换 DNS 服务或截获 HTTPS。
- 爱快数据仅在接口、版本和授权方式核实后作为可选适配器接入。不承诺旁路由天然看到全网。
- SQLite 采用批量写入、分层聚合、按时间与容量双重淘汰。限制主库、WAL 与缓存总预算，提前预留磁盘余量；空间不足时降低采集或暂停写入并提示。
- 诊断通过多目标、多层级证据判断可能原因。网络转发不依赖采集进程，异常时监测可停止而不改动路由。

## 集成前必须核实

1. 目标固件版本、架构、包管理器、可用内存、数据盘及挂载路径。
2. 主/旁路由实际转发路径、VLAN、IPv6、硬件加速和现有 DNS 组件。
3. 可访问的 ubus 对象、权限以及 nlbwmon/LLDP 数据覆盖。
4. 在测试环境验证安装、升级、卸载与完整回滚；未经实机验证不发布兼容承诺。
5. 首轮只读采集，核对界面与实际命令输出，测量长时间运行的 CPU、内存、数据库及写入量。
6. 确认存储预算和低空间行为后，再实现实际保留策略；真实告警稳定后再添加外部通知渠道。

## 第一版不包含

真实采集器、路由器安装包、DPI、自动修复网络、主路由配置修改、外部通知或云端账号。
